# چک‌لیست انتشار (هیچ‌کدام هنوز انجام نشده است)

الزامات ارسال به Unity Asset Store تغییر می‌کنند؛ پیش از ارسال، موارد جاری را در مستندات publisher آن بررسی کنید. این پکیج ارسال، تأیید یا منتشر نشده است.

- [ ] پکیج در Unity 6000.6 بدون خطا و هشدار کامپایل شود؛ موارد بخش *تست ← اجرا نشده* را رفع کنید.
- [ ] تست‌های EditMode در Unity Test Runner پاس شوند؛ نتایج را ثبت کنید.
- [ ] مجوز (license) را انتخاب و اضافه کنید (`LICENSE.md` فعلاً می‌گوید تصمیم باز است). بدون آن منتشر نکنید.
- [ ] صندوق ایمیل تماس را تأیید کنید؛ اگر تغییر کرد `package.json` و `Editor/Infrastructure/PackageMetadata.cs` را به‌روز کنید.
- [ ] نسخه و تاریخ انتشار را در `CHANGELOG.md` تعیین کنید (هیچ تاریخی ساخته نشده است).
- [ ] اسکرین‌شات واقعی از Editor بگیرید (جاهای خالی README)، تصاویر تبلیغاتی و در صورت تمایل ویدیوی کوتاه.
- [ ] ساختار Asset Store را تعیین کنید (معمولاً `Assets/<PublisherName>/AudioImportOptimizer/...`). پوشهٔ `Documentation~` را آنجا به `Documentation` تغییر نام دهید چون پوشه‌های `~` قابل import نیستند. `.gitignore`، `CONTRIBUTING.md` و در صورت تمایل `Tests` را کنار بگذارید.
- [ ] پکیج را در یک پروژهٔ تمیز دوباره import کنید؛ فایل اضافه نباشد و حذف پکیج چیزی باقی نگذارد (snapshotهای `ProjectSettings/JP/...` عمداً باقی می‌مانند).
- [ ] روی پروژهٔ بزرگ و روی Windows و macOS تست کنید.
- [ ] محدودیت‌های شناخته‌شده را در README و توضیح فروشگاه مرور کنید؛ ادعای کارایی یا کاهش حجم نکنید.
- [ ] بدون تصمیم خودتان commit، push یا upload نکنید.
